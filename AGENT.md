# Inside GENCO research instructions

## Research objective

Frame this repository around the falsifiable question:

> Is GENCO repeating one stationary correction rule, or executing a stage-specific learned correction schedule around a shared physics-feedback loop?

The released architecture is hybrid, not twelve fully independent blocks. Each correction has its own heterogeneous graph Transformer and bus/generator LayerNorm, while the bus/generator readouts, physics decoder, and residual-to-latent `physics_mlp` are shared across corrections. Describe parameter sharing at that level of precision.

The existing trajectory and bypass evidence shows that correction calls at different depths have different observed roles. It does **not** by itself prove that untied parameters are necessary: one shared operator can behave differently on different input states. Claims about parameter specialization require operator-substitution evidence; claims that untied training is better require a trained tied baseline.

Preferred wording before matched training is complete:

> We test whether GENCO's untied correction blocks exhibit stage-specific functional specialization.

Do not write that the project has proved untied parameters are necessary unless a fair trained comparison supports that statement.

## Architecture and intervention invariants

- Correction 1 is a transition stem: its graph block consumes `hidden_dim` and produces `hidden_dim * heads`.
- Corrections 2–12 have compatible `hidden_dim * heads` inputs and are the valid domain for cross-step operator substitution or recurrent-tail sharing.
- Whole-correction bypass is valid only for corrections 2–11. Correction 1 changes width; correction 12 owns the returned readout.
- The correction-12 graph update and readout affect the returned prediction, but its subsequently computed physics feedback is not consumed by another correction. Never use correction-12 `h_out` as evidence of functional activity. Measure `h_in -> h_graph` and/or the step-11-to-step-12 physical-output change.
- Operator substitution must replace the source `HeteroConv`, bus LayerNorm, and generator LayerNorm together unless an experiment explicitly isolates normalization.
- Keep upstream code under `vendor/` unchanged. Add research adapters or model variants in this repository.

## Fair comparison requirements

For untied versus tied experiments, hold constant:

- dataset, frozen split, normalizer, batch construction, and number of unrolled corrections;
- loss definitions and weights;
- training-update budget and checkpoint-selection metric;
- evaluation conditions and physical metrics.

Report model parameters and measured runtime separately. Same-width tied and untied models have similar inference computation but intentionally different parameter counts. Do not attribute a same-width accuracy gap solely to stage specialization without discussing capacity. Use at least three seeds for a confirmatory training comparison.

Required controls:

- original untied model;
- strict recurrent tail with a shared graph block and shared LayerNorm;
- shared graph block with step-specific LayerNorm;
- optionally, a roughly parameter-matched narrow untied model or a multi-stage shared model.

## Reproducibility and outputs

- Every reported figure must be generated by a committed script from a committed compact result table or documented regenerable outputs.
- Never leave a result supported only by a PNG. Save condition-level rows when practical and a compact summary under `results/`.
- Preserve stable scenario/device identities, frozen selections, hashes, and checkpoint-state immutability checks.
- Do not silently overwrite incomplete or mismatched artifacts.
- Training commands must record the data split, initialization seed, optimizer schedule, loss configuration, update budget, checkpoint-selection rule, runtime, and relevant hashes.
- Do not launch expensive training implicitly. Provide the exact command and wait for the user to run or explicitly authorize it.
- Run `.venv/bin/python -m unittest discover -s tests -v` after implementation changes. Run the smallest relevant research job before full regeneration.

## Narrative and figures

The main narrative should proceed as follows:

1. GENCO shares its physics loop but uses depth-specific correction blocks.
2. Latent representation geometry stabilizes before physical feasibility converges.
3. Bypass and feedback interventions show that late computation remains useful.
4. Operator substitution tests whether similar latent states imply interchangeable correction blocks.
5. Trained tied controls determine whether depth-specific parameterization improves the accuracy–parameter tradeoff.

Keep early stopping and correction skipping out of the main claim. Compute-policy figures belong in supplementary material. Prefer cross-checkpoint trajectory/CKA, physical-quantity trajectories, operator-substitution matrices, and accuracy-versus-parameter plots in the main story.
